# 构建与部署边界

`src + content + config + mods.lock.json` 是一份版本的完整输入。构建只读取这些输入和指定游戏目录里的编译引用，输出第一方插件及已跟踪设置。旧的生成器和临时更新包不再自动参与。

运行时规则从 mod 自身目录加载。旧召唤事件通过核心服务端 mod 关闭，感染者逻辑保留；不再要求修改原版 `seasonalevents.json`。关键配置仅有一个明确归属，第三方设置由 `config/overrides` 按目标相对路径部署。

第一方源码包括核心服务端、核心客户端、战后伤情/投保界面与预设直接返回。第三方源码和二进制不收进 Git；`mods.lock.json` 记录当前确切文件与程序集元数据。当前依赖组合不在整理阶段裁减。

安装前核验目标游戏基底和冲突模组，拒绝越界路径及指向其他目录的重解析点。所有变化先暂存并验散列，之后才备份和原子替换。任何提交异常恢复已改文件。日志、真实角色、账号和用户其他文件不在载荷路径允许范围内。

同一目录可重复安装、更新和依次回退。新版本只清理上一版拥有的过期文件；本地修改默认产生可见冲突。目标路径、端口和角色类型是安装时状态，不写入仓库或开发者机器路径。

测试分为合成安装/回退测试、内容图与本地化校验、真实后端的原生 API 冒烟检查。真实后端通过不代表 UI、进战局、撤离保存和长期平衡都已验收。

本机工作流由 `Configure-Workspace.ps1` 配置私有实例路径，`Workspace.ps1` 统一调用当前构建、发布安装器与校验器。安装状态格式 2 额外记录 BepInEx 配置键值散列，区分自动排版和真实参数修改；SVM 预设另以只规范化 BOM 与换行的文本散列识别编码改写。格式 1 可在下一次安装时升级。该状态不存储账号值或角色数据。
