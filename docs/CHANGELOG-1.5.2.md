# 1.5.2 · 部署加载

部署时只预热本局固定感染者池真正需要的类型、难度与数量，不再预热关闭中的原生备用刷怪和万圣节额外尸群。通过原生缓存接口顺序写入，每个请求最多 100 份，省去原生反复切片及等待。本局实体仍按有限波次进入，整局预算、持枪者、掉落和刷点保留。

实机回归发现只缓存首批会触发原生缓存不足时的异常请求，因此正式实现保留整局固定总量的资料预热，避免把加载时间转移成局内补员问题。原生单体领取与角色创建流程保持原样。

感染者服务端缓存最小批量从 30 降到 6；若客户端本次确实请求更多，原生服务端仍满足请求量。有限波次模式显式关闭原生 NewSpawn 和非波次分组入口，避免绕过整局预算。

点击部署后临时将 Unity 异步载入优先级提高，开始入场读秒时恢复原值；返菜单、加载失败和退出也会释放这项临时设置。没有调整画质或原生倒计时长度。

增加部署、地图、物资对象池、角色资料准备、读秒开始和正式开局的分阶段日志，按单次加载编号关联，供之后直接排查慢在哪一步。

配置统一位于 `config/gameplay.json` 的 `loading` 节点，构建时生成客户端配置。可单独关闭加速，分阶段诊断仍保留。

本机实测与验证范围见 [验证记录](VALIDATION.md)。
