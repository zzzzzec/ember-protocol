# Ember Protocol

- The repository is the source of truth. `src/` owns code, `content/server/` owns game data, and `config/` owns settings.
- Preserve quest, condition, recipe, trader and offer IDs during maintenance. Never copy real player profiles into this repository.
- Target SPT 4.0.13 and EFT 0.16.9.40087. Require matching engine hashes before deployment.
- Build using explicitly supplied game references; never commit game assemblies, external mod binaries, account data, logs, backups or generated packages.
- Keep player and development installations separate. Never stop the player's game or backend to run a test.
- Deployment must use an owned-file manifest, path validation, backups and rollback. Do not delete unowned files or modify character saves.
- Run the content validator and deployment integration tests after relevant changes. Native API checks do not imply live game UI or in-raid acceptance.
- Third-party dependencies remain unmodified and external to Git. Pin exact files and require their source installation or a private dependency archive.

## Local development workflow

- This checkout is the canonical development project. Runtime installation directories and their legacy `Tools/ZombieSurvival` sources are deployment/history, never build inputs.
- Read `.local/workspace.json` for the actual Player/Development roots and toolchain. Keep those machine paths, dependency archives, profiles and diagnostics out of Git.
- Use `tools/Workspace.ps1 -Action Install -Instance Development` to build, install and verify changes for isolated testing. The default instance is Development; pass Player explicitly for a playable update.
- Player uses port 6969 and the current independent Development backend uses 6974. Do not reuse the legacy 6973 backend beneath the player installation.
- Use `-Action BackendCheck -Instance Development` only against the dedicated test role. Never submit test quest completion or profile reset requests to Player.
- When gameplay work is ready for the user, deploy through the installer to the requested instance. Never patch runtime files as the permanent implementation or stop an active player's game/backend to install.
- Development supports an isolated full QA client. Keep a separate QA account, launcher settings and logs; set its launcher IsDevMode=true for port 6974 and launch from its SPT directory. API or install checks still do not imply game UI, combat, FPS or post-raid acceptance. Never use a real Player account for test fixtures.
- Preserve real BepInEx setting changes; only comments, order and formatting may be treated as equivalent during install/verify/rollback. Duplicate or malformed keys do not get equivalence handling. SVM preset equivalence only normalizes BOM, line endings and trailing newlines; keep every JSON setting character significant.

- Keep deliberate partial recovery: basic AI-2 quota is three per completed deployment, not enough medicine to guarantee a full heal after every death. Bleeding/fracture supplies must still permit treating those injuries.
- The approved legacy-health migration only recognizes the old 950 HP SVM body-part pattern, scales each current body-part value proportionally to standard 440, preserves injury effects, and records a one-time migration. Never use it as a free heal.
- Classic loan stages issue the rifle, parts and seed ammunition once per quest. Never add automatic replacement or reissue on death/reaccept. Equivalent same-model rifles with required attachments may be returned; do not bind returns to the originally issued item ID.
- Keep Ground Zero's fixed raid total at 30 infected including one shooter. The user now requests steady finite replenishment: only the initial capped population opens the raid, then vacancies refill one actor at a time with staggered actual activation, rather than waiting for two survivors and releasing a batch. Total never grows; stop replenishing when the fixed reserve is exhausted. Count pending native creation requests in the simultaneous cap, bound outstanding reinforcements, and pace actual creation as well as request dispatch. Preserve one-time spawn/death accounting, position safety and per-raid cleanup. Higher danger should consider local building density; never confuse native spawn-zone counts with a measured map area.
- Infected may investigate copied sound or sighting positions, but must not receive a live unseen player reference through native global pursuit or report propagation. Reuse low-frequency loops and diagnostics; protect the user's 60 FPS target.
- Player startup is manual: use SPT.Server.exe and SPT.Launcher.exe in visible user-owned windows. Do not start the Player backend hidden or through a combined CMD launcher. ServerOnly automation is restricted to Development.

- Medicine, supplies and valuables retain vanilla reference values. The approved 2.2 ammunition revision uses config/ammunition.json and tools/rebalance_ammunition.py for reproducible caliber/flesh/penetration prices, with the cheapest cash offer as the resale reference. Generated retained ammo packs contain their printed quantity; spawn scarcity and loose-ammunition caps remain. Packaging has a positive 1 RUB shell reference because the native quote sums its cartridge children. Never refill owned inventory on login or repeat rewards. Authored weapon/attachment resale references still deduct attached parts and preserve native wear/resource deductions. Review barter, crafting and Fence after price changes.
- Quartermaster loyalty requires levels 1/8/18/30 and standing 0/.2/.5/.9; Fence regular-customer access requires level 20 and standing 6. Existing reputation is preserved and native loyalty is recalculated.

- Night-truck choice commits when accepting aid1/cargo1, not on completion. Persist the native choice ledger, fail the opposing choice, hide its follow-ups, and keep death/restart/replayed requests from reopening either route or duplicating rewards.
- Trader repair is Quartermaster-only. Repair kits retain native wear/resource mechanics; never reduce durability loss or replace lost kits as a recovery shortcut. Invalid kit requests must not mutate inventory.

- Idle patrol must use independent local centres and staggered timers. Apply soft separation only while idle; valid sound/sight information overrides it so local hordes can form. Do not restore shared five-member leaders, add live unseen player references, force spawn relocation, or add per-frame path searches. Keep bounded neighbour scans and patrol diagnostics.

- The approved 2.0 generator plans one seeded fixed population per raid. Preserve role quotas and simultaneous caps. Never buy unseen player tracking with threat points. Native zombie root-motion scaling must preserve vertical movement, collisions and navigation; keep armor visual/combat equipment separate from corpse drops. New-start testing uses separate disposable accounts; never reset existing Player saves.

- User-authorized local administration uses Admin.ps1 and the startup-only local queue. Never enqueue real-profile grants or quest changes as QA or without a concrete user request. Preserve backups, per-command audit and replay protection. Success marks only; compensation is a separate explicit grant. Native admin acceptance is Development-only and requires two controlled restarts.

- Opening availability is authored in opening.json: two initial tasks, seven additional lane gates over the first six main tasks. Preserve native Started/AvailableForFinish/Success states and counters when adding gates; never clear already accepted quests to reduce UI exposure. New specialist contacts and transferred offers come from the contacts list; keep each offer in one window and migrate its personal purchase count once. Recognize completed prerequisites without repeating rewards. Persisted departed/dead/suspended contacts remain closed on login. The current narrative covers all thirty existing main tasks with Rin, Nina, Claire, Emma, Katya and Haruka plus Fence; the full six-character fate system remains future work. Keep basic carrying equipment, early guns/ammunition and all existing loan contracts at Rin. Katya only receives industrial ammunition/protection offers already gated by main sixteen or later; Emma handles optional upgraded carrying equipment. Haruka opens after main twenty-two, receives the two existing main-twenty-four laboratory-card offers, and uses config/procurement.json for her limited new supplies. Preserve native material/valuable valuations and FIR requirements.
- Authored quest acceptance and completion endpoints must preserve active progress and ignore completed replays. Serialize their state check with native processing and save successful completion before releasing that gate. Only record story.completed after the native quest has actually reached Success; another prefix can decline completion after our guard. Keep strict authored story handovers and loan checks; never reissue a loan or duplicate XP, standing, messages or attachments when requests repeat. Native status checks do not constitute crash-atomic transactions or actual combat objective acceptance.
- Quest illustration assignments are authored in content/narrative/quest-illustrations.json and compiled by tools/compile_quest_art.py. Preserve approved Style A identities and existing avatars; keep new raster assets owned, hashed and packaged. Static character-workspace images are not promises of visitable NPC scenes, escorts or story outcomes. HTTP image checks do not imply client layout or in-raid acceptance.
- New family-reply choices are authored in config/story-decisions.json and content/narrative/family-replies.zh-CN.json, compiled with tools/compile_story_decisions.py. Acceptance only prepares; native completion commits the displayed payload and withdraws the opposing draft. Keep exact recipient/scope/content/hash receipts per profile, preserve native mutual-exclusion Fail conditions and make duplicate failure callbacks harmless. Legacy night-car acceptance commitment remains unchanged. A prepared or failed completion-stage draft must never recover as sent. Test both routes, concurrent sends, death before/after sending and controlled restarts using disposable Development accounts.
- Native EventOutputHolder is not safe for overlapping item requests. Keep the item-event gate through asynchronous response cloning/reset and release it exactly once on success or fault; a quest-controller monitor begins too late to protect that lifecycle. Do not introduce a per-frame client loop for this menu/backend concern.
- Rare collection sources are authored in data/quest-loot.json. Add only the listed templates to existing weapon-container distributions at their minimum map ranks; preserve pre-existing weights, counts, spawn points and third-party positive entries, and keep repeated application idempotent. Register through native StaticLoot.AddTransformer: its Value is re-deserialized on every read, so a one-off in-place change has no persistent effect. Native location dictionary keys differ from playable IDs for Factory and high-level Ground Zero: resolve Location.Base.Id. Never insert oversized melee items into zombie pockets or broaden the corpse whitelist to solve world-loot availability. Source-table and native-generation evidence does not prove a player's world pickup or full-campaign completion.
