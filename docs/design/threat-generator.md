# 固定感染者名单与威胁预算

`config/threat-generator.json` 是生成器参数入口。部署时生成一次名单，战斗中不根据玩家装备、击杀或剩余弹药改变敌人属性。现有有限波次负责释放，整局名单可耗尽。

## 评分与规划

`src/shared/ThreatPolicy.cs` 同时供服务端、客户端和规则测试使用。分值是可校准的设计估计，不是精确死亡概率。血量、速度、视距、视角、听觉倍率、反应时间、护甲、头盔和持枪均计价；高速配厚甲、持枪配装甲另有组合成本。

先为每个名额抽取磨损，再在固定持枪数量、类型比例、普通类型下限、单体分值和装备渲染成本约束内升级组合。磨损不允许被升级策略重新抽取以追求高耐久。随机种子、最终名单、磨损编码、实际使用分值和缓存余量分别记录。满额预算无法在约束内用完时保留余额。

原生最小资料缓存批次可能返回多于波次需求的资料；额外缓存资料不增加波次总数，也不转化为额外实体。类型和磨损使用专用 NPC ID 命名空间传递，保留唯一性后缀；服务端与客户端修订号必须一致，不借用昵称、武器或技能字段保存状态。

## 实际应用

服务端设置部位血量，装入原版完整头盔、护甲、内衬和插板树，并按磨损编码设置剩余耐久及修复上限。新增装备不进入常规掉落白名单。

客户端按个体使用原生丧尸水平根运动、低频视听门控和反应时间。垂直运动、导航及碰撞保持原生路径，不增加逐帧寻路。有效目视、物理接触和真实声音仍是获取信息的前提。

感染者骨架可能没有原版插板碰撞体。兼容层仅在这些生成的感染者受击时，将胸部朝向映射到前、后或侧插板，把简化头部表面映射到顶部、后脑、耳部、眼睛或下颌。插板先于内衬处理。穿透、跳弹、钝伤、耐久和生命扣除继续由原生逻辑执行。普通玩家的护甲逻辑不经过该兼容映射。方向与分区是简化近似，不伪称具有标准角色的完整板片几何。

## 性能与诊断

名单只在部署准备阶段计算。装备种类有限；实体总量、活跃加待生成上限和装备渲染预算分别约束。增加装备仍有资源加载、绘制与受击计算开销，必须用真实场景观测。

服务端事件 `threat.plan` / `threat.profile` 记录种子、名单、磨损和评分；客户端 `threat.actor` 记录个体参数、原生护甲组件与简化骨架兼容状态。原生 `combat.damage`、波次和性能日志继续保留。

开发专用 `tests/ClientWaveProbe` 不属于发布项目。合成弹道合同明确标记为 synthetic，不冒充实弹轨迹或普通玩家战斗；免伤和批量死亡也不能作为正常开荒难度证明。
